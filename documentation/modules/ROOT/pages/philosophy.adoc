= Why Metarr?

NOTE: The short version lives in the README — this is the full story.

== Metadata is king

Metadata is usually the most valuable part of large systems.  Our lives are more about our metadata than you may realize. 

Lets buy a toy on Huge-Online-Retailer.com. To you, its a basic transaction.  Huge-Online-Retailer deposited a few dollars profit, you get your toy, you move on.  But, what if Huge-Online-Retailer doesn't just get the order, what if they also have your location when you placed the order.  That location metadata changes the transaction into something more interesting because it reveals you were standing in Brick-And-Mortar-Store at the time. Now Huge-Online-Retailer can gamble they have an exploitable advantage on that toy in that area because, based on purchase location, one can reasonably assume Huge-Online-Retailer is either selling it for less than Brick-And-Mortar-Store or Brick-And-Mortar-Store doesn't have it. This information is then used to automatically adjust the real-time marketing on the toy and end up selling a few more than they normally would have because it turned out Brick-And-Mortar-Store was out.  Turned one sale into a few, by itself, a lot of work for not much.  Now replicate this process hundreds of thousands of times a day and you begin to realize how the big guys really make their money.

That small piece of metadata, your location, transformed a simple purchase and you were completely oblivious to it.  This is the bedrock foundation of how all modern "rule your life" algorithms work — all driven by multi-billion dollar metadata collection companies.

So, what is metadata in a media collection? Simple: the data is the movie file itself; metadata is everything else. Even the file name is considered metadata because its telling you whats inside the file. Metadata includes all the information in the credits of the movie, cast, crew, production studios, then extends to poster images, background images, and more. All of this information is crucial to a media collection.

== So what's different about Metarr?

Yes, I know — another *arr app claiming to be different. So what's actually special about Metarr? To explain, let's first describe a typical media server installation:

* A NAS sharing your files.
* Radarr pointing at that share looking for new movies.
* Jellyfin playing your movies.

Consider what's going on here from a metadata perspective.

* When you ask Radarr to download a movie, it calls TheMovieDB to get the metadata about that movie. This is how Radarr knows the cast, what the poster image is, and so on. When Radarr downloads the movie, it can optionally write that metadata to the directory — this is your NFO file and images. 
* Jellyfin has its own metadata management system that completely ignores Radarr. It can either manage the metadata in its own database or, optionally, write everything back to the media files directory.

So what is the system of record for the metadata? It's now stored in Radarr, in Jellyfin, and on the shared drive — which copy is the truth? Metarr answers this. It treats the files in your shared drive as the source of truth, manipulating those "records" (the files themselves) directly, then notifying other systems like Radarr and Jellyfin that something changed, letting them take care of themselves.

All the downloaders in the *arr suite support writing metadata, but that capability is limited by the number of sources they use and the different formats involved. Stack more systems on top of your media library — TV tuners, image systems, and the like — and maintaining the metadata becomes nearly impossible. TinyMediaManager does an okay job, but it has some serious limitations.

== Gen AI position

A moment of honesty: the code in this project represents many man-years of hand-written work. Metarr's concept and feature set were in the works for years before a single directory was created. The code design is based on the architecture of modern, high-speed, event-driven, distributed applications that I have been building for a long time.

I didn't build Metarr until now because I know first-hand what it takes to build these types of systems. The age of Gen AI has made building systems like this without a team of dozens of developers possible. Considering this project "vibe-coded" is not accurate at all. It is a well designed system, using a modern architecture and the most appropriate tools to solve their intended problems.

If you have issues with Gen AI software and choose not to use it or contribute to this project, I respect that completely.  Gen AI is changing the world as I know it and I'm not sure how to think about it either.  But the simple truth is the only other way this project would be possible is with a venture capital level investment of money and man power.
