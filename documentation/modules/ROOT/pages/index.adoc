= Metarr Documentation

Metarr manages the metadata of a media collection, treating the files on your
shared storage as the system of record rather than any one application's
database.

If you want the reasoning behind that stance before anything else, start with
xref:philosophy.adoc[Why Metarr].

== Project status

Metarr is under active development and is not a finished product. This
documentation describes *what the software actually does today*. Where a
capability is designed but not yet built, the page in question says so
explicitly rather than staying silent — a gap you cannot see is worse than one
that is written down.

.Working end to end
* *Library scanning* — agents walk your libraries, classify everything they
  find, and the server stores the result. See xref:scanning.adoc[Library Scanning].
* *Agent fleet management* — deploy agents, watch presence and telemetry, map
  each library onto the path that machine knows it by. See xref:agents.adoc[Agents].
* *Configuration and security* — every setting above the connection layer is
  editable at runtime. See xref:configuration.adoc[Configuration].
* *Logging and observability* — structured logs from both binaries, a live tail
  in the UI, optional shipping to OpenObserve. See xref:logging.adoc[Logging].
* *Workflow authoring and validation* — a graph editor over a node catalog,
  continuously validated. See xref:workflows.adoc[Workflows].
* *An AI assistant* that can read the workflow you are editing and propose
  changes to it.

.Not built yet
* *Workflow execution.* Workflows are authorable, savable, versioned and
  validated. Nothing runs them.
* *Sonarr data fetching.* Instances are configurable; no Sonarr API call is
  ever made.
* *Radarr, TMDB, TVDB, Plex and Jellyfin integration.* Metarr reads provider IDs
  out of NFO files that already exist. It does not call those APIs.
* *Scheduling and automation.* No cron, no timers, no triggers.
* *Searches, Automations and Tasks.* Present in the navigation marked "soon",
  with no pages behind them.
